## 4. 아키텍처 — ECB + Dual-Track

### 4.1 의존 방향

```
boundary → control → entity
entity → (control|boundary|*) import 금지
```

### 4.2 Dual-Track

| Track | 레이어 | Mock | 테스트 ID | 파일 패턴 |
|-------|--------|------|-----------|-----------|
| **Logic** | entity, control | Domain Mock **금지** | `D-*` | `test_d_*.py` |
| **UI** | boundary | Mock **허용** | `U-*` | `test_u_*.py` |

- Logic·UI **한 테스트 파일에 혼합 금지**.
- `pyproject.ini_options.markers`: `entity`, `control`, `boundary`.

### 4.3 Report 01 ECB 매핑 (변경 없음)

| Layer | Harness 시점 | 이후 |
|-------|--------------|------|
| Entity | 패키지만 | `MagicSquare`, `Cell`, `MagicConstant` |
| Control | 패키지만 | `SquareValidator`, Command |
| Boundary | 패키지만 | E001~E007, `int[6]` 출력 |

## 5. TDD 정책

1. **RED → GREEN → REFACTOR** (단계 생략·구현 선행 금지).
2. **assert 완화 · `skip` · `xfail` 금지**.
3. Mom Test 증거 연계 첫 Logic RED 후보:
   - **D-001** (가칭): 대각-only FAIL → `FAIL(diagonal)` / E005
   - **D-002** (가칭): `validate_grid` 1회 10선
4. **MagicConstant** 단일 모듈 후 비즈니스 코드에서 `34`/`16` 직접 사용 금지.
